# michi — キャラクターコーチToDo

キャラクターコーチToDo設計パック v1.3（2026-09-28）を基準にした、端末単独版の実装です。このリポジトリにはアプリのソースコードを収録しています。

## 起動

Node.jsとnpmを用意し、このリポジトリのルートで以下を実行してください。

```powershell
npm ci
npm run desktop
```

Windows用ポータブル版を作る場合は `npm run package:win` を実行します。日時付きのフォルダーが `release` に生成され、その中の `michi.exe` で起動できます。`release` はGitHubに含めていません。HTTPサーバー、ログイン、APIキーは不要です。保存先は実行したWindowsユーザープロファイル内のアプリ専用IndexedDBです。

開発時は `npm run dev`。型検査とビルドは `npm run build`、自動テストは `npm test`、静的検査は `npm run lint`。ブラウザ版は初回の読み込み後、同じブラウザの保存領域にデータを保持します。デスクトップ版とは別の保存領域です。

Electronのローカル接続・PC操作・通知の検証は `npm run test:electron`、全CJS構文検査は `npm run check:electron`。UbuntuとWindowsのCIでも実行します。

記憶の選択送信・保持期限、資料と会話の統合文字検索、端末内読み上げ・本人音源、共通通知、承認付きファイル接続・固定PC操作を追加しました。確認範囲と未接続機能は[今回の検証記録](docs/verification-2026-10-01-local-bridge.md)と[121要件の進捗](docs/requirements-status.md)を参照してください。

LINEの本人エクスポート、選んだDiscordメッセージJSON、Web引用、ローカル `.eml` の取込と、ICS予定の差分確認を追加しました。新規資料のAI送信・通知・外部書込・開示は初期無効です。選択したタスクのMCP接続については[取込とMCPの検証記録](docs/verification-2026-10-01-imports-mcp.md)を参照してください。

本人が指定したポイント・期限・タイトルの代理編集と、証拠付き実績のGitHub公開を追加しました。公開機能の確認範囲と未接続機能は[代理編集と実績公開の検証記録](docs/verification-2026-10-01-approvals-achievements.md)を参照してください。

本人が相談文に指定した毎週・毎月第N営業日・選択活動からの相対周期を、AIの候補から確認できます。検証済み資料の周期候補も、本人が適用条件・暦・期間・時刻を選んで採用します。設定の保存と発生回の反映は別々に確認します。[周期補助の検証記録](docs/verification-2026-10-01-routine-assistance.md)を参照してください。

完了取消後に親のポイントを子へ配分した場合、再完了には配分後の残額を使います。初回実績と既存台帳、本人による実績訂正を保持します。[配分と再完了の検証記録](docs/verification-2026-10-01-allocation-completion.md)を参照してください。

取消した実績を新しい点数で確定する場合は、完了履歴またはタスクの「実績を再確認」から、点数と理由を入力します。元記録・子の実績・外出グループへの影響を確認して保存し、将来用の見積もりは保持します。[本人再確認の検証記録](docs/verification-2026-10-01-completion-reconfirmation.md)を参照してください。

営業日カレンダー・公開勤務表の固定形式CSVは、繰り返し画面から端末内で取り込めます。勤務表は本人の公開済み行だけを保存します。資料の保存後、共通カレンダーで発生回の差分を確認して予定へ反映します。更新できなくなった取込元は「取込元の終了」で終了し、新しい取込元へ移行できます。対応形式・サンプルと検証結果は[CSV取込の検証記録](docs/verification-2026-10-01-calendar-csv-import.md)にあります。

## 実装済み

- 手動タスク作成・編集・検索、Inbox相当の一覧、予定日と締め切りの分離、階層プロジェクト・ラベルグループ・重要度、ゴミ箱と復元
- チェックリストの子タスク化とポイント配分、版付きタスク・プロジェクトテンプレート
- ノート（本人記述・出典の区別）、コメント、ハッシュ付きローカル添付（最大5MB）
- 12段までのカテゴリ・プロジェクト階層、循環・アクセス境界の検証、子タスクからのポイント集計。旧プロジェクト名は起動時に移行
- 既存タスクを付箋として配置するWall。位置とグループの変更はタスクの完了状態やポイントに影響しません
- PCとスマートフォンで別々に選べるナビゲーション。全項目を隠しても上部の機能検索と設定ボタンから戻せます
- 既存機能の表示ON/OFF。画面を隠しても保存済みデータと通知設定は維持され、機能検索から再表示できます
- Workflow Library：表示・ナビゲーション・日々の目安を版付きで保存・適用・共有。共有JSONにAPIキーや送信許可は含めません
- テーマ、アクセント色、画面倍率、アイコン線の設定。ポイント種別とエラーは色に加えて文字でも表示します
- チェックリストの進捗記録と、親の確定ポイントから配分する子タスク化
- AIなしのQuick AddとBraindump。最大100行の事前確認、行別の手動ポイント編集、正常行のみの登録、一括atomic保存
- 文章から最大20件のタスク入力。OpenRouterの引用候補と明示された値を確認・編集し、承認したdigestへまとめて保存。AI停止時も原文下書きを使用
- 選択したタスク本文から負荷属性を見積もり、項目別に採用・訂正。手動ポイントを維持し、評価IDに推定の根拠を保存
- revision検査付きの一括編集。競合があれば選択全件を変更せず、画面に通知
- 未設定・手動0pt・手動値・式計算・推定範囲の区別。設計書第6章の既定式
- IndexedDBのローカル正式保存、revision競合、command key再送抑止、評価履歴、完了・取消・再完了・訂正の台帳
- 今日、7日計画と時間／ポイント容量、集中タイマーと作業時間、実績画面。重複作業区間はunionで集計し、元区間と訂正履歴も表示。Windows版には状態を共有する集中用小窓があります
- 開始可能日が未来のタスクは今日の候補から除外して一覧で延期を表示。見直し日は作業完了と分けて今日の画面に表示
- 本人が予約する見直し日の通知、反復催促、静かな時間、通知上限。Windowsの許可時はOS通知。アプリ終了中は次回起動時に判定
- 朝夕・週次レビューの本人回答、元の計画、実績、要約を別保存。再計画しても元の計画を維持
- 日・週・月・完了後のローカル繰り返し、除外日、今回だけの発生回編集、安定した発生回キーによる重複防止
- 勤務・授業の共通カレンダー。本人の適用曜日・期間・営業日順位と、選択した予定JSONの休日・振替・勤務変更・公開シフトを照合。確認後に反映し、完了実績と発生回IDを保持
- ICSファイルの読取専用取込。UID・繰り返し回・版で照合し、資料の保存と予定への反映を別々に確認。元カレンダーへ書き戻さず、予定だけからタスク・締切・点数を作りません
- LINE／Discordの選択ファイルを、話者・日付・タイムゾーン・原文位置と一緒に取込。話者本人の対応は明示確認し、全履歴・全DMの自動収集とは表示しません
- Web選択引用とローカルメールの範囲確認。MIMEの本文とHTML・添付を分け、選択本文と元ファイルのhash・出典を保存
- 複数作業と移動を同じ外出束に配分。固定加点と最低20ptを一度だけ適用し、手動ポイントの置換は別確認。完了後の束は固定
- 選択した資料の原文・版・引用位置・取得範囲・保存期限を端末内へ保存。取得、保存、検索、AI送信、通知、外部変更、開示を別許可で管理
- 資料からの必要タスク候補を専用Inboxへ保存。検出と検証を別API呼出に分け、本人確認後に登録。未採用候補はタスク件数とポイントに含めません
- コーチ会話と入力途中の下書きの保存、端末内検索、本人文・AI文・定型文の区別。本人についての記憶を明示／推測に分け、訂正・削除・出典を保存
- コーチによる既存タスクの変更案。メモ・予定日は承認または設定した上限内で適用。タイトル・本当の期限・具体的なポイントは本人が指定値を確定してから確認し、期限・ポイントは個別確認も必須。評価履歴を追加し、既存の完了記録と実績台帳を維持
- 証拠付き実績のローカル草稿と公開説明。原本と本人が編集した公開用文章を分け、既定40pt・証拠・公開条件を照合。専用GitHub接続では正確な送信先と全5ファイルを毎回確認し、承認した初回投稿だけを実行。結果不明時は再送を停止
- アプリ内キャラクターの定型対話。Windowsデスクトップ版では任意のOpenRouter接続で、送信文と選択したタスク・目標の現行チェックインについてAIに相談できます
- パスワード由来鍵（PBKDF2-SHA256）とAES-256-GCMによる `.coachbundle` 書き出し／整合確認後の復元。復元前に参照・日時・台帳・設定も検証
- version付きJSONの書き出し・検証後の復元、タスクCSV・ICSの書き出し。JSON・CSV・ICSは暗号化なし
- Windows用Electronシェル。外部AIとGitHubへの通信は、許可された操作をメインプロセスから実行。APIキーと実績用GitHubトークンはそれぞれOSの暗号化保存を使用

## 任意のOpenRouter接続

Windowsデスクトップ版の「コーチ」画面でモデルIDとAPIキーを設定します。既定のモデルIDは `deepseek/deepseek-v4.1-flash` です。キーはOSの暗号化保存を使って端末内に保存し、GitHubや `.coachbundle` バックアップには含めません。接続を削除するとキーも端末から削除します。ブラウザ版にはAPIキー入力を提供していません。

接続後は、保存済みのDay Notes本文と目標チェックイン回答を選んでOpenRouterで要約できます。AI要約は本人の本文・回答と別に保存され、訂正履歴が残ります。コーチ会話では送信する目標を選択でき、現行の回答・要約だけを送ります。

「設定とデータ」の利用上限で、日・月・処理別の回数とトークン予算を設定できます。送信前に予約し、通信失敗・タイムアウトも予約を保持します。APIから報告された使用量と結果不明の回数を分け、費用が分からない場合は不明と表示します。自動AI処理の予算は0です。

利用記録は再起動時にも整理し、前月以後に開始・精算した記録と進行中の予約を保持します。再起動時に応答待ちだった予約は、結果不明として今日の利用へ残します。[AI利用記録の検証記録](docs/verification-2026-10-01-ai-usage-retention.md)を参照してください。

AIチャットは送信した文章と、画面で選択したタスクのタイトル・メモ・予定日・期限・ポイント、選択した目標の現行チェックインをOpenRouter経由で選択したモデルの提供先へ送ります。選択資料の送信は、資料画面の個別要約・検出操作で行います。過去の会話や他のタスクは自動送信しません。キー未設定またはオフラインのときは端末内の定型応答を利用できます。AIをOFFにすると待機中の変更案・応答の採用権限が失効します。

必要タスク検出は同じ選択モデルによる検出・検証を使い、自動登録は行いません。独立モデルによる評価は未完了です。検出候補、既存タスクの変更案、共通ルーティンの周期補助は、それぞれ差分を確認して適用します。資料本文の命令や自己申告の承認フラグから許可を変更できません。

資料取得は本人が選択した文章・エクスポートの手動取り込みです。外部サービスの全履歴や最新状態を取得したとは表示しません。資料を削除すると原文、要約、検索用派生データ、検出候補、資料由来の記憶とAI応答を削除し、独立した本人入力や登録済みタスクは保持します。

## 任意のローカルMCP接続

Windows版の「設定とデータ」→「ローカルエージェント接続」で、共有するタスクと項目を選択して接続し、現在の内容を書き出します。「stdio対応MCPクライアントへ接続」から、この接続専用の設定JSONを表示できます。クライアントへの登録は別操作です。

`michi_snapshot` は選択項目の読取、`michi_propose_update` / `michi_propose_create` は案の提出、`michi_command_result` は結果ファイルの読取です。変更案はアプリで本人が確認して保存します。署名鍵・APIキー・全資料・全会話をMCPへ渡しません。外部結果は未検証コピーとして返し、実保存と署名はアプリ側で確認します。

起動設定には実行ファイル、同梱 `scripts/michi-mcp.mjs`、選択した接続フォルダー、`ELECTRON_RUN_AS_NODE=1` が含まれます。Node環境では `npm run mcp:stdio -- --bridge <接続フォルダーの絶対パス>` でも起動できます。stdioの新旧プロトコルに対応しますが、ChatGPTクラウド等のHTTP接続・OAuthサーバーと、各製品の実アカウント試験は未提供です。接続取消後の新しい読取・提出は拒否します。既に相手が取得したコピーの回収は保証できません。

## 任意の証拠付きGitHub実績

「実績」の「証拠付きGitHub実績」で、完了実績の公開用草稿と証拠の説明を保存できます。元の添付・ノート・会話は投稿せず、本人が独立して編集・確認した文章だけを公開ファイルに含めます。原本の存在やhashは成果の真実性を保証しません。

実際の投稿には、本人所有の初期化済みリポジトリと、その対象だけにContents書込権限を設定した専用GitHubトークンを登録します。アプリ開発用の `gh` 認証は利用しません。トークンは端末内へ暗号化保存し、バックアップへ含めません。既定の閾値は40ptで、公開内容・repository・可視性・branch・path・README置換は毎回確認します。

GitHub標準のcontribution graphと、端末内や公開したポイント図は別です。100ptの完了から100commitは作りません。commitの保存確認後も、標準の草への帰属・反映は未確認と表示します。空リポジトリ初期化、保護branchのPR作成、訂正の実送信、GitHub App OAuth、クラウドStorageの証拠検査は未接続です。実アカウントへの投稿試験も未実施です。

## データについて

バックアップのパスワードは復元時に必要です。紛失するとアプリは回復できません。復元は現在のデータセットを置き換えるので、必要なら事前に書き出してください。ブラウザデータを消すと端末内データも失われるため、定期的に外部保存先へ書き出してください。
