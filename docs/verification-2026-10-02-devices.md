# 端末間の引継ぎ・移行・複製とタスクのファイル共有

対象は I05（複数端末対応・同期）と I06（Task Sharing）です。設計 17.2・17.4・18.11、画面 S18・S19 のうち、サーバーなしで実現できるファイルによる範囲を実装しました。自動同期や接続型の共有とは表示しません。

## I05 手動の引継ぎ確認

- 暗号化バックアップ（`.coachbundle`）に引継ぎ情報を追加しました。`bundle_id`、種類（backup／move／fork）、データセットID、書き出した端末ID、基準にしたファイルID（`base_bundle_id`）だけで、項目は完全一致で検査します。タスクごとの状態（heads）は保存せず、比較のたびに行から再計算します。
- 端末IDは端末内の別表に作り、バックアップに入れず、復元でも置き換えません。書き出し・取込確認のたびに、その時点のタスクのheads（タイトル・メモ・手動ポイント・予定日・締め切り・状態・完了実績など）と記録IDの一覧を端末内に残し、次の書き出しの基準にします。
- 取り込むファイルを内容検証すると「手動の引継ぎ確認」を表示します。同じデータセットでは、タスクごとに「同じ／取込ファイルだけ変更／この端末だけ変更／両方で変更／片方だけにある／要確認」に分け、基準・この端末・取込ファイルの値を並べます。手動ポイントの違いは「手動」と強調し、完了と実績の違いは要手動対応とだけ表示して台帳を統合しません。
- この端末だけの変更、両方の変更、要確認、または台帳・完了記録などこの端末だけにある記録があれば、そのままの置き換えはできません。選択肢はキャンセル、この端末を正本として維持、この端末を書き出してから置き換え（書き出しが成功した後でだけ置き換え）、項目別の取込です。
- 項目別の取込は通常の版検査付き更新で、新しい評価履歴と `adopted_from_handoff:<bundle_id>` の監査を追加します。台帳と完了記録は書きません。取込ファイルだけにある未完了タスクは同じIDで取り込め、完了記録のあるタスクは要手動対応として拒否します。
- 別データセットのファイルは件数を示した「別データセットで置き換え」の確認がなければ置き換えません。旧形式（引継ぎ情報なし）のファイルも従来通り復元できますが、違いはすべて要確認になります。
- ダッシュボードの保存状態は「最終引継ぎ: 日時（手動の引継ぎ確認）」または「最終引継ぎ: なし（単独モード）」です。「同期済み」「マージ済み」とは表示しません。

## I05 移行と複製

- 移行: 「この端末から移行」の実クリックで送出側を凍結し、移行ファイルを書き出します。受入側は検証後に置き換えて有効化し、8文字の完了コードを表示します。コードは移行IDと暗号化ファイル内だけにある秘密値から計算するため、ファイルを開いた受入側だけが示せます。送出側でコードを入力すると読み取り専用になり、コード前なら取消で再開できます。書き出しに失敗した場合も再開します。
- 凍結と読み取り専用は端末内の別表に持ち、業務表（タスク・評価・完了・台帳・ルーティン・作業時間・ノート・コメント・添付・習慣・目標・カレンダー等）への書込みを IndexedDB の同じトランザクション内で拒否します（`DATASET_FROZEN`、日本語の理由つき）。保持期限の整理、資料の消去、旧メモからの引用分離、本人の明示的な復元は凍結中でも実行し、復元は端末を有効に戻します。ルーティンの自動生成は凍結中に止め、起動時追い付きも0件で実体を作らず、コーチ通知とスヌーズ通知の予約も行いません。Top of Mindの小窓も同じ状態を表示します。
- 複製（fork）: 新しいデータセットIDと系譜（複製元・祖先・日時）を持つ独立コピーを書き出します。実績の公開設定・証拠・公開履歴、ファイル接続の許可記録は複製せず、通知予約は再承認が必要な取消状態にし、AI許可を切ります。複製元の端末は変わりません。
- 同時に編集し続けるにはサーバー接続が必要（このバージョンでは未提供）と画面に表示します。別端末に残ったコピーを遠隔で停止・削除できるとは表示しません。

## I06 ファイルでの共有スナップショット

- 端末ごとに WebCrypto の ECDSA P-256（署名）と ECDH P-256（鍵合意）の鍵を作り、秘密鍵は取り出し不可のまま端末内の別表に置きます。公開鍵の名刺と、公開鍵のSHA-256指紋（4文字区切り）を交換し、別の方法で照合した相手にだけ共有できます。
- 共有はタスク単位の付与（閲覧・コメント・編集の提案）で、共有する項目（タイトル・状態・予定日・締め切り・ポイント）を選びます。送る内容は暗号化前の全文を表示してから書き出します。メモ・コメント・添付・評価履歴・監査・検出の根拠・出典のID・題名・件数は含めません。タイトル内の出典リンクは隠し、タイトルに個人資料の原文が20文字以上含まれる共有は共有メモと同じ規則で拒否します。相手へのメモは、個人資料の原文と20文字以上一致する場合や出典参照を含む場合に拒否します。
- `.michishare` は ECDH の一時鍵＋HKDF-SHA256 で導いた AES-256-GCM 鍵で暗号化し、ヘッダーと暗号文に ECDSA 署名を付けます（最大5MB）。受け手は、自分宛て→共有元の指紋（初回は本人が照合して登録）→署名→復号→項目の完全一致→版の巻き戻し・再生の拒否、の順に検査します。
- 受け取った項目は「共有された項目」の別表だけに保存し、自分のタスク・今日・ポイント・台帳・資料検索には入れません。出典を開くと、実在する資料IDでも架空のIDでも同じ「共有されていない出典です」になります。
- 取消は権限の版を上げ、署名した取消ファイルを書き出します。受け手が取り込むと表示が消え、古い付与ファイルは拒否します。相手の端末にあるコピーは遠隔削除できないと表示します。
- コメント権限の相手は返信ファイル（`.michireply`、相手が署名し共有元宛てに暗号化）でコメントを返し、共有元は相手の名前つきで一度だけ追加し、タスク画面でも共有相手の名札つきで表示します。編集の提案はタイトルと予定日だけで、共有元が本人の指示として確認し、通常の変更案（ChangeSet）を実クリックで承認するまで何も変わりません（反映の監査にファイル入口・外部依頼の根拠・提案IDを残します）。手動ポイントと締め切りは提案できません。取消後や権限変更前の返信は拒否し、役割を下げた後に残った編集提案の確認も拒否します。確認済み相手の名刺が別名で再取込されたら指紋確認は外れ、再照合が必要です。
- 共有の鍵・相手・付与・受信・提案の表はバックアップに入れません。

## 残る範囲

- 実スマートフォンでの PC↔スマホ同時編集の確認は未実施です（AT-I05 の文面どおりの受入には実機が必要なため、I05 は一部実装のままです）。
- サーバー接続型の同期（送信待ちキュー、commit順の変更フィード、snapshot と RESNAPSHOT、サーバー側の項目別競合解決、S19 /sync/conflicts の送信待ち・無効な操作）、同時編集の継続、通信のない別端末の強制停止・遠隔削除は未提供です。
- 引継ぎの比較はタスクの主要項目と記録IDの有無までです。ピン留めなどの表示用フラグ、習慣・目標など他の表の同じIDの内容変更は比較しません。台帳・完了記録の統合は行いません。
- 凍結の対象は業務表（タスク・評価・完了・台帳・カレンダー等）だけです。設定画面の表示設定、資料・記憶・会話の追加、共有ファイルの書き出し、GitHub実績の公開操作は凍結中も止めません。
- 共有は接続型ではなくファイルでの共有スナップショットです。期限付き招待、受信者の本人確認のサーバー検査、サーバー側ACL、即時のキャッシュ失効、共有チャンネルでのコーチ、contributor 権限、共有した相手による完了・作業記録は未提供です。所有者が「ファイル共有を接続型共有の代わりとは認めない」と判断した場合、I06 は一部実装に戻します。
- 共有は同一PC上の別プロファイルを相手役とした確認で、別の実在人物・実アカウント・別端末との確認ではありません。上記のWindows画面の確認は一時プロファイル2件のエミュレーションで実施済みです（実機2台・実スマホでの確認ではない）。
