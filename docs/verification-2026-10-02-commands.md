# 変更の共通受付（コマンドバス）・変更の確認と履歴・代理分割・外部からの系列編集

対象は設計20・28・29章と4.8・14章（K12・N03、画面S04・S06・S09・S21）、受入例AT-K12・AT-N03です。外部の入口は、この端末のファイル受信箱とローカルstdio MCP（N06/N11）に限ります。N09/H01（操作別の自動化設定・停止）の上に追加し、判定は既存の操作表をそのまま使います。

## K12：一つのコマンドバス

- `src/command-bus.ts` に共通のコマンド形式（`schema_version`・`command_id`・`type`・`target_id`・`expected_revision`・`payload`・`basis`）と、入口ごとの操作者（`ui_human`・`ui_coach`・`file`・`mcp`）を追加しました。操作者はアプリ内の入口だけが作り、複製・JSONから戻した操作者は `ACTOR_UNVERIFIED` で拒否します。
- 形式は完全一致で検査します。`approved`・`actor`・`policy_level` などの項目、未登録の操作（完了・削除・権限など）、未対応の項目は受け付けません。入口ごとに名乗れる根拠も固定です（アプリは `app_instruction`、ファイル/MCPは `external_request`）。
- 判定と適用は既存のChangeSet（digest・版・本人・dataset・epoch・期限・保護項目・本人指示・native click）に任せ、業務ロジックを重複させていません。実効権限は「N09の操作表 ∩ 接続の許可（項目・操作・移動日数・範囲内自動の委任）」です。毎回承認の接続から来た案は、操作表が範囲内自動でも自動になりません。
- 結果は共通の語彙 `applied / awaiting_approval / denied / conflict / expired / rejected / failed` と安定したコードで返します。入口固有のコード（`REVISION_CONFLICT`・`TARGET_OR_REVISION_INVALID`・`FIELD_NOT_GRANTED`・`SIGNATURE_INVALID` など）は対応表で共通コードへ読み替えます。AI変更の停止中に起きた権限変更は、停止（`CHANGES_STOPPED`）を優先して返します。
- S06（選んだタスクの変更相談）、ファイル受信箱、ローカルMCPの3入口をこのバスに通しました。承認カードはどの入口も同じ `ChangeSetPreview`（分割は `TaskSplitPreview`）です。ファイル/MCPの承認は従来どおりメイン側の一回限りのリースで包みます。
- ファイル/MCPからの期限・本人指定ポイント・タイトルは、接続で許可した場合だけ受け付けます。外部の値は依頼として表示し、本人がアプリ内で値を確定（実クリック）してから差分になり、さらに保護項目の個別確認と最終承認が必要です（S06と同じ。設計28.9 `external_request`）。従来の `UNSUPPORTED_FIELD` にはなりません。
- 署名付き結果ファイルに `denied / conflict / expired / rejected` とコードを追加しました。受信したが開いていないコマンドは `recordRejected`、適用中の拒否はリースの取消に理由を付けて、メイン側が署名します。DBに受領記録がある場合は常に「適用済み」が優先します。`michi_command_result` はこれらを `isError: true` とアプリと同じコードで返します。コードのない旧形式の結果ファイルは従来どおり読めます。
- `changeset.update` の監査に入口・根拠・コマンドIDを追加しました（判定の自動/承認は既存）。ファイル/MCPの受領監査も入口（`file`/`mcp`）と根拠を記録します。
- ログアウト・復元・AI停止で、バスと分割の一時権限も破棄します（停止スイッチでは確認待ちの案を残し、適用時に停止として拒否します）。

## K12：変更の確認と履歴（S21）

- 既存のS21（設定とデータ内）を「変更の確認と履歴」に広げました。新しい画面は増やしていません。
- 承認待ち：このアプリ内で準備した変更案（S06・ファイル・MCP）と、受信箱で受け取ってまだ開いていない外部コマンドを並べます。入口、操作者（作成者ではありません。コーチはモデル、外部エージェントは接続ID・自己申告のクライアント名）、対象と版、項目の変更前→変更後、保護項目、確認期限を表示します。「この変更だけ許可」と「今後の権限設定へ」は別のボタンです。後者は自動化設定（S20）へ移動するだけです。ファイル/MCPの案はメイン側のリースを使うため、許可はローカルエージェント接続の同じ承認カードで行います。
- 履歴：本人の直接編集、コーチ・外部エージェントの変更、分割、ファイル/MCPの受領、周期・暦の設定と反映、作成補助・検出の登録、PC操作、実績公開の承認を50件ずつ表示します。操作者、入口、自動/本人が承認/本人の操作、承認者、設定版、根拠、内容digestを示し、旧形式の文章だけの記録も「旧形式の記録」として表示します。ICS・CSVの本文、資料の引用、PC操作の出力は表示しません（必要な項目だけを読み出します）。
- 監査記録から表示するだけで、再実行・承認はしません。代理変更の取り消しは従来の本人確認付きの取り消しを使います。

## K12：本人の直接編集の監査

- タスク編集、一括編集、フラグ、完了・完了取消・実績訂正、ゴミ箱・復元、分割ウィザードの監査を、他の入口と同じ構造（入口 `ui_human`、本人、操作、変更項目の前後、版の前後、コマンドキー）にしました。本人の編集には新しい承認や権限判定を加えていません。
- 監査は既存の書込トランザクション内で書き、失敗すると編集・評価・受領記録ごと取り消します。長い値は2,000文字で切ります。バックアップの検証は監査の本文を文字列として扱うため、旧形式・新形式のどちらも復元できます。

## N03：代理分割

- 分割ウィザードの保存処理を共通化し（`applyTaskSplitInTransaction`）、ウィザードと代理分割が同じ配分・完了の同期・共通外出の保護・チェックリスト連携・監査を使います。ウィザードの既存テストは変更なしで通過します。
- 分割は新しい変更の種類です（`src/task-split-change.ts`）。親が未完了で本人確定のポイント（manual/allocated）を持つこと、2〜20件、整数で合計が親と一致することが条件です。分割は自動になりません（操作表の `task.split` は停止か毎回確認だけ）。本人指定ポイントの保護確認が必ず必要です。
- S06に「AIで分割候補を作る」を追加しました。子タスク名は本人の相談文にある言葉だけ、ポイントは本人がその作業に書いた整数だけを候補にし、それ以外は未設定にします。「半分にして」「いい感じに分けて」などは送信せず、変更案も作りません。未設定の配分は本人が入力するまで差分を作りません。
- ファイル/MCPでは `task.split`（MCP `michi_propose_split`）を、本人が分割を許可した接続だけで受け付けます。外部の名前と配分は提案として表示し、本人が確定してから同じ分割カードで承認します。
- 承認後、親は0ptの配分済みになり新しい評価を追加します。子は配分ポイントで作成し、評価に「本人指示による代理」の由来（操作者・モデル・承認者）を残します。台帳は子の完了時だけ増えます。

## N03：外部入口からの系列編集

- ファイル/MCPの `routine.change`（MCP `michi_propose_routine_change`）を、本人が選んだ系列だけで受け付けます。書き出すのは系列のID・版・名称・周期だけです（事実・資料・完了記録は書き出しません）。
- 依頼は周期（毎週・営業日・活動基準）と範囲（今回だけ・この回以降・未完了すべて）だけです。名称・点数・手順・有効期間は変えません。本人が依頼内容を確認して実クリックすると、根拠 `external_request`（モデルなし、依頼したエージェントIDを記録）の周期指示になり、次の10回を表示します。設定の承認後も、発生回の反映は共通カレンダーの別の承認です。同じコマンドIDの再送で設定は一つだけです。
- 共通カレンダーの保存処理は、外側のトランザクションを保つため digest 計算を `Dexie.waitFor` で包みました（判定・結果は変わりません）。
- S06の時刻付き締め切り（N05の `dueAt`）もバスを通り、本人指示と締め切り・時刻それぞれの保護確認が必要です。外部入口は時刻付き締め切りを受け付けません。

## 残る範囲

- LINE・Telegram・Discord・Slackなどのメッセンジャー入口（承認ボタンの署名）と、実際のChatGPT・Claude・Codex・Claude CodeからのリモートMCP（HTTPS/OAuth）は外部アカウントが必要なため未接続です。この記録の外部入口は端末内のファイル受信箱とstdio MCPだけです。
- コーチの回答はテストでは合成文字列です。OpenRouterの実モデルでの分割提案は試していません（有料・AT-N03の対象外）。モデルの品質ではなく、権限と検証の論理を確認しています。
- 自動化設定を変えるとepochが進み、外部接続は取り消されます。確認待ちだったコマンドには停止・失効の理由を署名して返しますが、取消後に新しく出されたコマンドは接続の取消として拒否され、再接続が必要です。
- 外部からの系列編集は毎週・営業日・活動基準の周期だけです。RRULE・完了起点の系列（N05）は接続の系列選択に出さず、書出し・依頼とも拒否します（アプリの繰り返し画面で本人が変更します）。ラベル・所属・チェックリストの代理編集（設計4.8）は未追加です。
- 外部からの分割・系列変更の結果ファイルは対象（親タスクまたは系列）だけを示し、作成した子タスクや発生回の詳細はアプリの監査に残します。
- S21はアプリ起動中に準備・受信した案だけを承認待ちとして表示します（案は保存しないため、再起動後は受信箱を再確認します）。
- Windows画面での実操作 parity（S06/ファイル/MCPの同一カード、停止時の同一コード、分割・系列の実クリック適用）は未確認です。実MCPクライアント、Android実機も未確認です。
