# 営業日カレンダー・公開勤務表のCSV取込

M06のローカルCSV読取を共通カレンダーの照合へ接続します。形式・列名・順序は固定で、本人が対象・期間・保持期限を明示して選びます。サンプルは架空の予定で、公式の営業日・勤務割当を示しません。CSV取込はAIや外部providerへファイルを送信しません。

- [営業日カレンダーのサンプル](examples/business-calendar.csv)
- [公開勤務表のサンプル](examples/published-roster.csv)

## ファイル形式

UTF-8のCSVを選びます。BOM、CRLFとLF、引用符内のカンマ・改行・二重引用符を扱います。列の数・名前・順序、日付、時刻、版、状態を検証し、不正な文字列、引用符、行数・ファイルサイズ（1MiB）の上限違反は保存前に拒否します。

| 種類 | 固定ヘッダー |
| --- | --- |
| 営業日カレンダー | `record_id,record_revision,date,status` |
| 公開勤務表 | `shift_id,record_revision,person_ref,published,status,start_date,start_time,end_date,end_time` |

- `record_revision`は1〜2147483647の整数です。同じレコードIDはファイル全体で一行だけにします。期間外の行も重複として扱います。
- 勤務表は本人の`person_ref`とUnicode正規化（NFC）後に完全一致し、公開済みの行だけを対象にします。前後の空白や大文字小文字は同一視しません。別人・下書きの行は件数だけ表示し、保存しません。
- 開始日と終了日を別に指定するため、22時から翌6時の勤務も表せます。夏時間で曖昧・存在しない時刻は推測しません。

## 取込元と識別

- 本人の確定済み参加条件・カレンダー・活動・期間・タイムゾーン・保持期限・取込元IDを選択します。勤務表は曜日指定のない専用活動だけに取り込み、通常の週次活動は変更しません。
- 一つのカレンダー・勤務活動に有効な取込元は一つです。同じ対象の新しい取込元は、既存の取込元を「取込元の終了」で終了するまで作れません。
- 勤務の発生回は、活動と外部シフトIDから決まり、取込元に依存しません。取込元を移行しても同じ予定・タスクを更新し、二重に作成しません。同じ本人の別の勤務活動に、同じシフトIDで時間の重なる行がある場合は取り込みません。
- 外部IDと本人識別子は、SHA-256による仮名IDとして保存します。推測しやすいIDは照合で特定されうるため、匿名化とは扱いません。

## 更新と生成

- 「変更なし」は、本人に適用する選択行のhash・対象・期間・資料名・保持期限で判定します。ファイル全体のSHA-256は記録用で、他者の行、BOM、改行、行順だけの違いでは新しい版を作りません。
- 同じ版の異なる内容と古い版は拒否します。終了した取込元の版も比較し、移行先の新しい取込元で古い資料を最新にしません。
- 取込済みレコードの新しい版が取込期間外へ移った場合は、期間を広げるまで拒否し、古い日時を最新として扱いません。
- 欠落・空ファイル・下書き・別人の行は取消に使いません。明示した`cancelled`・`withdrawn`だけが取消・取り下げです。
- 資料保存は本人が差分を確認して行い、タスク・予定・実績台帳を変更しません。次に共通カレンダーの生成差分を確認し、別の本人操作で適用します。本人が編集・着手・完了した回は既存の保護を維持します。取込元の移行で出典だけが変わった回は確認待ちにしません。
- 本人がルールを停止・変更した場合だけ、勤務表に基づく未完了の準備タスクを通常の範囲指定で取消します。以後の変更の境界日は勤務日で判断し、移動した勤務は最新の版の日付で判断します。

## 保持期限と出典

- 選択した行の原文、行位置、版、引用hashを資料内に保存します。監査には取込元の概要（記録ID・版・状態・取込ごとのhashと行数）だけを残し、原文・CSV本人識別子・引用hashを複写しません。本人が設定した参加条件の本人識別子は設定値として保持します。
- 勤務表の根拠には現地の開始・終了日時も保存し、保持中の原文はタイムゾーン規則に依存せず照合します。規則の更新で同じ版のUTC時刻が変わった場合は、資料の矛盾ではなく規則更新として案内します。
- 保持期限は取込元単位です。短い期限で取り込むと、以前の記録の原文にも同じ期限を適用し、その件数を確認案に表示します。長い期限で以前の期限を延長しません。
- 期限到達後は原文と資料由来の本人識別子を消去し、その資料から新しく生成しません。既存の発生回ID、日時、完了と台帳を保持します。バックアップを復元しても、現在までに消去・短縮した原文の保持は元に戻しません。

## 取込元の終了と上限

- 一つの取込元に保存する記録は100版・5000行・1000レコードまでです。重複した古い記録は取込時に整理します。上限、本人識別子・タイムゾーンの変更で更新できない取込元は「取込元の終了」で終了し、新しい取込元へ移行します。原文の保持期限が切れただけの取込元は、同じ取込元へ再取込して更新できます。
- 終了は本人の実クリックで承認します。終了した取込元の行は新しい予定・タスクの根拠にせず、確認待ちの保留もしません。保存済みの根拠・監査と、反映済みの予定・完了・台帳は残し、勤務の取消とは扱いません。終了時に原文とCSV本人識別子を消去することもできます。
- 共通カレンダー全体の事実は5000件までです。終了と移行を繰り返すと、旧取込元の事実も履歴としてこの件数に含まれます。

## 検証

全体のVitest 104ファイル1,045件とElectron/Node 128件、合計1,173件が通過しました。lint、Electron CJS 21ファイルの構文確認、TypeScript・Vite・PWAビルドも成功しています。

複数の観点に分けたレビューを3回行い、各指摘を別の確認者が再現試験で検証しました。確認された問題は修正し、回帰試験を追加しました。主な回帰試験は次の内容です。

- 他者の行・BOM・改行・行順だけの違いで版を増やさない。重複した旧記録の整理と、20版を超える実際の更新。
- 同じ対象の新しい取込元の拒否、終了後の移行で同じ発生キーへ対応、終了済み取込元より古い版の拒否、二つの有効な取込元の矛盾の確認待ち。
- 期間外の新しい版・重複ID・版の上限・NFC、タイムゾーン規則の更新後の照合と案内、原文に別の行を混ぜた改変の拒否。
- 保持期限の短縮と開示、復元時の再適用、監査の概要化、終了時の原文消去。
- ルール停止・以後の停止・対象変更による準備タスクの取消、境界日の版選択、別の勤務活動の同じシフトID、月次ルールの確認範囲。

Windowsのポータブル版（試験用プロファイル）で、実クリックによる51項目を確認しました。

- 選択欄はすべて空欄から開始し、明示選択がない差分作成・不正なUTF-8・合成クリックでの保存を拒否しました。資料保存ではタスク・予定を作りませんでした。
- 共通カレンダーの別承認で、CSVの休業日を除いた第4営業日（5月7日）にタスクを1件作成し、再生成は変更0でした。版2の休業日移動で同じタスクを5月10日へ移し、古い版の再取込は拒否しました。タスクを完了（5pt）した後の部分ファイルでは、完了済みのタスク・完了記録・台帳を変更しませんでした。
- 勤務表は本人の公開済み1行だけを保存し、他者・下書き・期間外を件数だけ表示しました。夜勤22時〜翌7時を1件の予定にし、日時変更は同じ予定を更新、行の欠落では取消せず、明示取消だけで該当の予定を削除しました。
- 同じ活動への別の取込元を拒否し、取込元の終了は合成クリックを拒否して実クリックだけで保存しました。終了後も予定・実績を保持し、取消・新規作成は0件でした。
- 保持期限を約3分後にした取込元で予定を作り、起動中のアプリの期限処理で原文と本人識別子が消えることを確認しました。予定・タスク・完了・台帳は保持し、生成差分は確認待ちのまま作成・取消0件でした。その取込元の終了後は確認待ちが解除され、取消は0件でした。
- 再読み込み後も資料・予定・既存の試験データを保持しました。
- 390pxの幅をエミュレートし、52要素と199文字領域にカード外のはみ出しがありませんでした。これはAndroid実機試験ではありません。

実アプリ試験で、有効期間が終わった月次ルールが期間外の月に「カレンダー未設定」の確認待ちを作り、全体の生成を止める既存の不具合を見つけて修正しました。

API呼出し0、キー読み取り0、AI IPC呼出し0を確認しました。試験後は通信ガードを解除し、AI停止・モデル設定・通常画面幅を復元しました。本番プロファイルは使っていません。
