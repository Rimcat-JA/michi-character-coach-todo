## App MCP read slice (later checkpoint)

The exact self-contained 15-tool catalog is vendored from design pack v1.3. A shared bounded schema validator checks input/output without fetching references. The core authenticates and rechecks current app/grant state before every call, including list/ping; revocation during an asynchronous read discards the body. Only five handlers are currently implemented: capabilities, task search/get, manual/unset score preview, and a non-disclosing context-search result. Other catalog tools explicitly return `FEATURE_NOT_IMPLEMENTED`; formula UUID rules are not supplied by the standalone formula registry yet. Summary provenance is conservatively unverified. The external command gate has 37 unit cases, but is not yet wired to these read-only handlers; the full 50-case reference/receipt port remains work.

`--connect <clientId>` uses a live app connection; `--bridge <root>` retains the signed-copy behavior. App credentials are random per client and per process, rotated when configuration is displayed again and dropped on revoke/stop/exit. They never use the signing key, BYOK key, files as authentication or serialized owner approval. The Windows-only transport uses a hidden Windows PowerShell 5.1/.NET Framework relay because Node's default Windows pipe ACL is insufficient. The relay creates the pipe with a protected DACL granting only the current SID, sets `PIPE_REJECT_REMOTE_CLIENTS` before acceptance, relays bounded UTF-8 JSON lines, and stops with the app. A restricted execution policy or unavailable runtime fails closed; no execution-policy bypass is used. Actual DACL read-back was verified on Windows; another-user account test was not executed. [Microsoft named-pipe security](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights), [NamedPipeServerStream](https://learn.microsoft.com/en-us/dotnet/api/system.io.pipes.namedpipeserverstream).

Windows DEV evidence on the isolated `qa-reminders-profile/external-ai` profile is in `work/L-ui-evidence.json` in the calling Codex workspace. Actions use actual Chromium `Input.dispatchMouseEvent` trusted clicks. No physical mouse, external account or packaged launch is claimed. The checks cover: plugin/BYOK OFF task creation with 25pt; native external grant while BYOK remains OFF; local self-test read; app pipe exact 15-tool listing and same task ID/revision/25pt as UI; actual CLI validate/submit with stable replay; no save before approval; native approval changes only scheduled date; points/deadline/ledger preserved; post-application replay makes no second commit; old live credential denied after revoke; local revoke self-test; external OFF preserves coach OFF/profile. QA app and relay were shut down afterward. No connection credential is stored in the evidence file.

This advances Windows DEV evidence for N06, but does not complete N11 or the batch. Grant revision editing, remaining ten business handlers, durable request-key semantics/basis verification, handoffs/context packages, HTTP/OAuth, scenario ledger and final PR validation still remain.
